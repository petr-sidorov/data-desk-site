# Тестовый запуск Data Desk в Coolify

## Создание приложения

1. В Coolify создайте приложение на основе GitHub-репозитория `petr-sidorov/data-desk-site` и выберите проверенную ветку, содержащую Dockerfile.
2. Укажите сборку из Dockerfile в корне репозитория (`/Dockerfile`), без отдельной команды сборки.
3. Установите внутренний порт приложения `3000` в поле **Ports Exposes**. Сервер слушает `0.0.0.0` и использует `PORT`, если Coolify задаст его; по умолчанию это `3000`.
4. Для первичной проверки используйте тестовый адрес, уже доступный в вашем Coolify. Не назначайте `datadesk.tech` и не меняйте DNS.

В образ попадают только файлы сайта, сервер и `api/contact.mjs`. Исходник API хранится отдельно от веб-каталога. Скрытые файлы, файлы вне веб-каталога и каталоги API не раздаются. Docker healthcheck проверяет `GET /healthz`.

## Переменные окружения

Добавьте переменные в **Environment Variables** приложения Coolify. Не записывайте их значения в репозиторий или Dockerfile.

| Имя | Назначение |
| --- | --- |
| `RESEND_API_KEY` | Ключ Resend; отметьте значение как секрет в Coolify. |
| `CONTACT_TO_EMAIL` | Адрес получателя заявок для тестовой копии. |
| `CONTACT_FROM_EMAIL` | Проверенный отправитель в Resend, например `Data Desk <no-reply@example.com>`. |

Для тестовой копии используйте подходящие значения получателя и отправителя. Отправка заявки требует всех трёх переменных. Сборка и healthcheck не отправляют письма.

## Проверка

1. После сборки убедитесь, что тестовый адрес открывает `/` и загружает CSS, JavaScript, изображения и логотипы технологий.
2. Убедитесь, что контейнер стал healthy по `/healthz`.
3. Проверьте, что `/api/contact.mjs`, скрытые файлы и пути за пределами сайта недоступны.
4. Отправку заявки проверяйте отдельно после добавления и сверки переменных окружения в Coolify. Реальный тест доставки отправит письмо на указанный `CONTACT_TO_EMAIL`; до этого шага форма здесь не проверяется отправкой.

База данных, постоянный том и изменения DNS для тестовой копии не требуются.
